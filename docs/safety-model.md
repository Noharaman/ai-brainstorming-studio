# Safety Model

このアプリは、他社製のAI CLIを利用者のマシン上で起動し、利用者のプロジェクトを読ませることを前提としている。その前提の下で「何を保証でき、何を保証できないか」を明確にするための文書である。

結論を先に書く。**現在のビルドは外部AI CLIを起動せず、AIにファイルを編集させない。** これは機能を作れなかったからではなく、作った機能の安全境界を証明できなかったからである。以下、脅威ごとに「何を測ったか」「どう判断したか」を記す。

---

## 中心にある原則

### 1. 保証できないものを保証と書かない
「おそらく安全」と「安全だと示せた」を区別する。示せていないものは、その旨を書くか、機能を止める。

### 2. Fail closed
安全性が未証明の間、機能は無効側に倒す。「未検証だが動くので有効のまま」は選ばない。

### 3. 権限は「フラグ」ではなく「オブジェクトの不在」で表す
読み取り専用を `write=False` で表現すると、フラグを立て忘れた経路が書き込み可能になる。そうではなく、**書き込み権限は `WriteGrant` オブジェクトが存在する場合にのみ発生する**。全コマンドビルダの既定引数は `grant=None`（＝読み取り専用）であり、grantの存在を知らないコードは構造的に権限を渡せない。

### 4. 利用者の設定を書き換えない
既存のログイン・モデル・provider設定はそのまま使う。安全のためであっても、利用者の設定ファイルを勝手に変更しない。この制約が、後述する複数の判断を決めている。

---

## 脅威1: モデルのツール制限では hook を止められない

**脅威**: AI CLIの「読み取り専用モード」は、モデルがツールを使うことを止める。しかし多くのCLIは起動時に *hook*（利用者が設定した任意のシェルコマンド）を実行する。hookはモデルのツール制限の外側で動くため、読み取り専用のはずの相談でもファイルが書き換わりうる。

**実測（Claude Code）**: 使い捨てプロジェクトに `SessionStart` hook（`touch HOOK_RAN_MARKER`）を置き、`claude --permission-mode plan --tools "" -p` を実行した。

- `--safe-mode` なし → **マーカーファイルが作成された**（hookが実行された）
- `--safe-mode` あり → 作成されない

**判断**: 全Claude実行に `--safe-mode` を付ける。`--bare` も hook を止めるが、認証を `ANTHROPIC_API_KEY` に強制するため採用しない（原則4に反し、API課金へ誘導することになる）。

**残る穴**: 管理者ポリシー（admin-managed）で配布された hook は `--safe-mode` でも無効化できず、アプリ側に検出手段もない。**したがってClaudeについてもOSレベルのread-onlyは保証できない。**

---

## 脅威2: MCPサーバはシェルサンドボックスの外側で動く

**脅威**: MCPサーバやpluginは、ファイル書き込みやネットワーク送信を行える。これらはシェルコマンドのサンドボックスの外側で動作し、Git差分にも現れない。つまり「サンドボックス内で読み取り専用」でも、MCP経由で秘密情報が外部送信されうる。

**実測（Codex CLI 0.149.0）**: `codex mcp list --json` を用い、モデルを呼ばずに確認した。

| 試行 | 結果 |
|---|---|
| `codex features list` | `hooks` / `plugins` / `apps` / `browser_use` / `computer_use` が **stable かつ既定で有効** |
| `-c mcp_servers={}` | 有効サーバ7件 → **7件のまま**（置換されない） |
| `-c mcp_servers.node_repl.enabled=false` | 7 → 6（単純名なら効く） |
| `-c mcp_servers.cloudflare-api.enabled=false` | **設定全体が壊れる**（`invalid transport`。サーバのテーブルをマージせず置換するため） |
| `CODEX_HOME` を捨てディレクトリへ | サーバは消えるが**ログインも消える**（原則4に反する） |

**実測（Antigravity CLI 1.1.22）**: `agy --help` 全文を検索した。

- **実行単位でMCP/pluginを無効化するフラグが存在しない**
- 管理手段は `agy mcp disable` / `agy plugin disable` のみ → 利用者の設定ファイルを書き換えるため採用しない（原則4）
- `--sandbox` は端末制限、`--disable-slash-commands` はskill展開のみで、いずれもMCP隔離の根拠にならない

**判断**: **CodexとAntigravityのスロットを停止**（原則2）。Claudeも脅威1の残る穴により同基準で停止。結果として外部AI CLIは3枠とも起動しない。

---

## 脅威3: 実行するコードはAIが書き換えられる

**脅威**: 「テストコマンドは固定argvなので、モデル出力からシェル実行へ到達しない」は誤りである。argvが固定でも、`npm test` が実行する `package.json` や `conftest.py` は、直前にAIが編集できる。

**判断**: 自動テスト実行を既定で停止（`config.RUN_TESTS_AUTOMATICALLY = False`）。検出したコマンドを表示するにとどめ、実行は利用者が自分のターミナルで行う。

**「実装を承認する」ことは「任意のコードを自分の権限で実行することを承認する」ことではない。** 承認ゲートはこの脅威の根拠にならない。

---

## 脅威4: 承認された範囲を超える書き込み

**脅威**: サンドボックスの `workspace-write` は「利用者が承認したフォルダ」を意味しない。設定ファイルが追加の書込先を足せるうえ、`/tmp` と `$TMPDIR` も既定で書き込み可能で、それらはアプリの差分に現れない。

**実測（`codex sandbox`）**: OSレベル隔離の第一候補として評価した。

- `--permission-profile` は**必須**で、プロファイルは利用者のCodex設定から解決される → **自分が管理しない設定から安全境界を導くことになる**
- `--sandbox-state-json` は未文書の内部形式（`PermissionProfileDe`、`sandboxCwd` は `file://` URI）
- 空プロファイルは**実際に隔離した**（root内・sibling・HOME いずれへの書き込みも拒否）
- しかし**書き込みを許可するフィールド名が特定できなかった**（`sandbox`/`mode`/`filesystem`/`sandboxMode`/`writableRoots` をすべて拒否）

`sandbox-exec`/SBPL はAppleが第三者向けにサポートしておらず、製品の基盤にしない。

**判断**: 「隔離しつつ、ここだけ書き込ませる」を表現する手段が現時点で無い。**AIによるファイル編集機能を停止**（`config.IMPLEMENTATION_WRITES_ENABLED = False`）。

## 実装されている境界

### 書き込みの三重ゲート
書き込みに到達しうる3箇所すべてで確認する。1箇所を誤って戻しても、古い保存データを読み込んでも、書き込みモードには到達しない。

1. `autonomy_controller.grants_write()` — 自動化レベルの能力判定
2. `write_grant.granted_after_approval()` — grant生成（承認済みでも拒否）
3. `ProcessRunner.run()` — プロセス起動直前（どの経路で来たgrantでも遮断）

### WriteGrant のスコープ
grantは `run_id` と `agent` の両方を保持し、`grant_for()` が両方を照合する。**Implementerに発行したgrantが同一runのCritic/Verifierへ広がらず、前回runのgrantが次のrunへ生き残らない。** 承認経路以外で構築されたgrantは `is_authentic` が偽になり、全ビルダで読み取り専用へ縮退する。

### サンドボックス境界
`ProcessSandbox` の唯一の規則は **「backendが無ければ実行しない」**。`UnavailableSandbox.wrap()` は例外を投げる（コマンドをそのまま返す実装にすると、最も楽な経路が非隔離実行になるため）。

backendは使用前に canary で自己証明する必要がある。実際にmarkerファイルを書いて**ファイルが出来たかどうか**で判定するため、「成功と自己申告するが実際は素通し」のbackendは失格になる。`active_verified_sandbox()` が入口であり、canary未通過のbackendは返さない。

**現在のcanaryの検査範囲は基本的なファイル書込のみ**（root内・sibling・HOME・`/tmp`・read-onlyポリシー）。network・`$TMPDIR`・外向きsymlink・子孫プロセス・環境変数・cancel/timeoutは**未検査**であり、実backend実装時に拡張する必要がある。

### Git チェックポイント
**アプリは commit / reset / clean / stash を一切実行しない。** 承認時点のcommitを記録し、事後の差分を提示し、取り消しコマンドを**提示するだけ**にとどめる。

Gitが復元できないものを特に扱う。未追跡ファイルと`.gitignore`対象ファイルは、承認時に一覧とSHA-256ダイジェストを記録する。削除も上書きも `git diff` には現れないため、ダイジェスト比較でしか検出できない。symlinkは**リンク先文字列**をダイジェスト対象にする（内容ハッシュでは付け替えを見逃す）。大きすぎてハッシュできないファイルは「未確認」と明示する — **確認していないものを「変更なし」とは言わない。**

### 秘密情報
redactionは呼び出し側ではなく**書き込み境界**で行う（`WorkspaceManager` / `ChatRoomManager`）。呼び出し箇所は十数か所あり、1つ忘れれば漏れるため。`chat_rooms.json` は保存直前に**dict/listを再帰的に**走査する（ルーム名は依頼文の先頭から生成されるため、本文だけを対象にしていた時期に漏洩経路になっていた）。

検出対象は、既知prefix（Anthropic / OpenAI / Google / GitHub / AWS / Slack）に加え、JWT、PEM private key本文、接続URI内のパスワード、および `*TOKEN*` / `*SECRET*` / `*PASSWORD*` のような**変数名による代入検出**。変数名自体は残すのでログの可読性は保たれる。

### プロセス制御
CLI実行は非対話・タイムアウト付き・キャンセル可能。テスト実行は独自プロセスグループで起動し、キャンセル・タイムアウト時はプロセスグループ全体をTERM→KILLする（直接の子だけを終了すると、テストランナーのワーカーが残る）。

---

## 保証しないこと

- **課金**: 各CLIの実行がサブスク枠か、credits消費か、API課金かを、このアプリは判定できない。認証・provider・接続先を変更しないことは保証するが、どう課金されるかは保証しない。
- **管理者ポリシーhook**: 前述のとおり無効化も検出もできない。
- **OSレベルのread-only**: サンドボックスbackendが無いため、外部CLIプロセスに対するOSレベルの制限は存在しない。これがスロットを停止している理由である。

---

## 再開条件

外部AI CLIとファイル編集を再開するには、以下を満たすOSサンドボックスが必要である。

- project root内への書き込みは成功する
- sibling、HOME、外向きsymlink、`/tmp`、`$TMPDIR` への書き込みは失敗する
- ネットワークに到達できない
- 秘密情報を含む環境変数を子プロセスへ渡さない
- 子・孫プロセスも同じ境界内にある
- cancel / timeout でプロセスグループが残らない
- **サンドボックス失敗時に非サンドボックス実行へフォールバックしない**

加えて、各CLIについて実行単位でhook / MCP / pluginを無効化できることを実証する必要がある。
